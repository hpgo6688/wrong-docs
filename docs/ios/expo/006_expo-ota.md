Expo 本身 **不直接提供传统意义上的“热修复（Hotfix）”功能**，但它通过 **OTA（Over-The-Air）更新机制** 实现了类似的效果，允许你在不重新提交 App 到 App Store / Play Store 的情况下，**动态地更新 JS/TS 代码和资源**。

---

### 🔥 什么是“热修复”？

热修复（Hotfix）通常指在 App 发布后，**无需重新发布版本即可修复 bug 或更新逻辑**，常见方式包括：

- 动态更新 JS/TS 代码
- 动态替换资源（如图片、样式）
- 有些框架甚至支持原生代码热修复（如 Android 的 Tinker）

---

### 🚀 Expo 的热更新（Hotfix）能力

Expo 提供的是一种 **基于 OTA 的热更新机制**，通过 **`expo-updates`** 模块实现。

#### ✅ 支持更新的内容：

| 类型                         | 是否支持               |
| ---------------------------- | ---------------------- |
| JS/TS 代码                   | ✅ 支持                 |
| 静态资源（图片、字体）       | ✅ 支持                 |
| 原生代码（如原生模块、插件） | ❌ 不支持（需重新构建） |

---

### ✅ 如何使用 Expo OTA 更新（热修复）

#### 1. 安装 `expo-updates`（如果你使用的是 Bare Workflow）

```bash
npx expo install expo-updates
```

#### 2. 发布更新

```bash
npx expo export --dev-client
npx expo upload:update
```

或者使用 `eas update`（推荐方式）：

```bash
eas update --branch production
```

> `eas update` 是 Expo 推荐的 OTA 更新方式，支持多环境、灰度发布等高级功能。

---

### 📦 OTA 更新 vs 热修复 的区别

| 特性                 | Expo OTA 更新                | 传统热修复（如 CodePush） |
| -------------------- | ---------------------------- | ------------------------- |
| 是否支持 JS/TS 修复  | ✅ 是                         | ✅ 是                      |
| 是否支持原生代码修复 | ❌ 否                         | ⚠️ CodePush 也不支持       |
| 是否需要商店重新发布 | ❌ 不需要（只要不改原生代码） | ❌ 不需要                  |
| 是否支持灰度发布     | ✅ 使用 EAS Update 可实现     | ✅ 支持（如 CodePush）     |

---

### 🧩 补充：Expo 支持 CodePush 吗？

Expo 官方 **不支持 CodePush**，因为它有自己的 OTA 系统。但如果你使用的是 **Bare Workflow**，你可以手动集成 CodePush。

---

### ❗注意事项

1. **更改原生依赖或配置（如添加插件）**，需要重新构建 App。
2. OTA 更新在 **离线状态下不可用**，需用户联网后拉取更新。
3. OTA 更新的大小、频率应合理控制，避免被 App Store 审核认为是“动态行为过度”。
