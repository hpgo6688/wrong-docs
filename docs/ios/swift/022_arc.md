## 自动引用计数
自动引用计数（ARC）是 Swift 用来管理内存的一种机制。它自动跟踪和管理应用程序的内存使用，以确保对象在不再需要时被释放。

#### ARC 的工作原理

1. **引用计数**：每个对象都有一个引用计数，当有新的引用指向对象时，计数加一；当引用被移除时，计数减一。
2. **释放内存**：当对象的引用计数为零时，ARC 自动释放对象所占的内存。

#### ARC 的优点

- **无需手动管理内存**：开发者不需要显式地释放内存，减少了内存泄漏和崩溃的风险。
- **性能高效**：ARC 在编译时插入适当的内存管理代码，对性能影响较小。

#### ARC 的注意事项

- **循环引用**：如果两个对象互相引用，导致引用计数无法降为零，就会产生循环引用。可以使用弱引用（`weak`）或无主引用（`unowned`）来解决。
  
  - **弱引用（weak）**：引用不会增加对象的引用计数，适合对象可能为 `nil` 的情况。
  - **无主引用（unowned）**：引用不会增加引用计数，且假定对象始终存在，不适合对象可能为 `nil` 的情况。

通过理解 ARC，开发者可以编写更高效和安全的 Swift 代码。



## 弱引用 与 无主引用区别


当然！下面是对 **弱引用（`weak`）** 和 **无主引用（`unowned`）** 的详细对比，包括它们的**相同点**和**不同点**，帮助你更好地理解和选择使用场景。

---

### ✅ 相同点（异同中的“同”）

| 特性                        | 描述                                                                       |
| --------------------------- | -------------------------------------------------------------------------- |
| **不增加引用计数**          | 两者都不会增加所引用对象的引用计数，因此不会导致循环引用（retain cycle）。 |
| **用于避免循环引用**        | 常用于两个对象互相引用的场景中，防止内存泄漏。                             |
| **只能用于 class 类型对象** | 只能引用类的实例，因为结构体和枚举是值类型，不存在引用计数问题。           |

---

### 🔁 不同点（异同中的“异”）

| 特性                 | `weak` 弱引用                                                             | `unowned` 无主引用                                                             |
| -------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **可否为 `nil`**     | 可以为 `nil`，必须声明为可选类型（`Optional`）。                          | 不可以为 `nil`，必须在对象被释放前仍然有效。                                   |
| **内存释放时的行为** | 被引用对象释放时，`weak` 自动变为 `nil`。                                 | 被引用对象释放后，如果访问 `unowned`，会触发运行时崩溃（野指针）。             |
| **语法要求**         | 必须声明为可选类型，例如：`weak var delegate: MyDelegate?`                | 必须是非可选类型，例如：`unowned var owner: Owner`                             |
| **适用场景**         | 对象可能会在其生命周期中变为 `nil`，如 delegate、闭包中对 self 的弱引用。 | 两个对象生命周期绑定，引用对象在当前对象释放前一定存在，如 child 引用 parent。 |
| **安全性**           | 更安全，访问前可判断是否为 `nil`。                                        | 不安全，访问已释放的对象会崩溃。                                               |

---

### 🧠 举个例子帮助理解

#### 使用 `weak` 的典型场景（比如委托）

```swift
class ViewController {
    var delegate: SomeDelegate?
}

class SomeDelegate {
    weak var viewController: ViewController?
}
```

- `viewController` 可能在某个时刻被销毁，因此使用 `weak` 是安全的。

---

#### 使用 `unowned` 的典型场景（比如闭包中捕获 self）

```swift
class Customer {
    var name: String
    var card: CreditCard?

    init(name: String) {
        self.name = name
        self.card = CreditCard(owner: self)
    }
}

class CreditCard {
    unowned let owner: Customer

    init(owner: Customer) {
        self.owner = owner
    }
}
```

- `CreditCard` 的生命周期完全依赖于 `Customer`，所以可以使用 `unowned`。

---

### ✅ 总结一句话

> **如果引用的对象可能变为 `nil`，用 `weak`；如果引用的对象在当前对象销毁前一定存在，用 `unowned`。**

## 闭包的强引用循环 与 解决
闭包（Closure）在 Swift 中是引用类型，它会**捕获并强引用**其作用域中的对象（包括 `self`），这可能导致**强引用循环（Retain Cycle）**，从而造成内存泄漏。

---

## 🔁 什么是闭包的强引用循环？

当一个对象持有一个闭包，而这个闭包又捕获并强引用了该对象（通常是 `self`），就会形成**强引用循环**：

### 示例：

```swift
class Person {
    var name: String
    var printName: (() -> Void)?

    init(name: String) {
        self.name = name
        printName = {
            print("My name is \(self.name)")  // 闭包捕获了 self
        }
    }

    deinit {
        print("\(name) is being deinitialized")
    }
}

var p: Person? = Person(name: "Alice")
p = nil  // ❌ Person 不会被释放，发生强引用循环
```

---

## ✅ 如何解决？

### 使用 **捕获列表（Capture List）** 来弱化对 `self` 的引用

Swift 提供了捕获列表 `[weak self]` 或 `[unowned self]` 来避免闭包中的强引用。

---

### ✅ 方法一：`[weak self]`（推荐）

```swift
class Person {
    var name: String
    var printName: (() -> Void)?

    init(name: String) {
        self.name = name
        printName = { [weak self] in
            guard let self = self else { return }
            print("My name is \(self.name)")
        }
    }

    deinit {
        print("\(name) is being deinitialized")
    }
}
```

- `weak self` 是可选类型，需使用 `guard let` 或 `if let` 解包。
- 安全，不会崩溃。
- 适用于 `self` 可能在闭包执行前被释放的情况。

---

### ✅ 方法二：`[unowned self]`

```swift
class Person {
    var name: String
    var printName: (() -> Void)?

    init(name: String) {
        self.name = name
        printName = { [unowned self] in
            print("My name is \(self.name)")
        }
    }

    deinit {
        print("\(name) is being deinitialized")
    }
}
```

- `unowned self` 是非可选类型。
- 更高性能，但如果 `self` 已被释放，会造成崩溃。
- 适用于 `self` 在闭包生命周期内**一定存在**的情况。

---

## 📌 捕获列表语法

```swift
{ [capture_list] in
    // 闭包体
}
```

- 可以捕获多个值，例如 `[weak self, weak delegate]`。
- 捕获列表位于闭包参数列表之前。

---

## ✅ 总结对比

| 捕获方式         | 是否可选 | 是否安全                       | 适用场景                    |
| ---------------- | -------- | ------------------------------ | --------------------------- |
| `[weak self]`    | 是       | 是 ✅                           | `self` 可能被释放           |
| `[unowned self]` | 否       | 否 ❌（若访问已释放对象会崩溃） | `self` 生命周期一定长于闭包 |

---

## 🧠 小贴士

- 如果你在 `UIViewController` 中使用闭包（如网络请求回调、动画、定时器等），**几乎总是需要使用 `[weak self]`** 来避免引用循环。
- Swift 的 `@escaping` 闭包（异步执行的闭包）更容易引起引用循环，务必注意捕获方式。
