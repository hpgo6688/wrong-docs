## 一个gorm查询中，哪部分是主查询

在 GORM 中，主查询通常是指查询的核心部分，即针对主表（或主模型）的查询条件和操作。以下是一个示例：

```go
db.Joins("Company").Joins("Manager").First(&user, 1)
```

* **主查询**：`First(&user, 1)`
  + 这里的主查询是针对 `User` 表的查询，条件是 `ID = 1`。
  + `First` 方法会根据主键查找第一个记录。

* **关联部分**：`Joins("Company").Joins("Manager")`
  + 这些是用于加载关联数据的部分，通过连接相关表来获取关联的 `Company` 和 `Manager` 信息。

主查询决定了从哪个表开始查询和基本的过滤条件，而 `Joins` 指定了如何加载关联的数据。

## 增加复杂度1

当然，下面是一个更复杂的 GORM 查询示例，涉及多个条件、排序和关联：

假设我们有以下结构体：

```go
type User struct {
    ID      int
    Name    string
    Age     int
    Company Company
    Manager Manager
    Account Account
}

type Company struct {
    ID   int
    Name string
}

type Manager struct {
    ID   int
    Name string
}

type Account struct {
    ID   int
    Type string
}
```

查询示例：

```go
var users []User
db.Joins("Company").Joins("Manager").
    Where("users.age > ?", 25).
    Where("companies.name = ?", "Tech Corp").
    Order("users.name desc").
    Limit(10).
    Find(&users)
```

### 解析：

* **主查询**：
  + `Find(&users)`：这是主查询部分，目标是从 `User` 表中获取记录。
  + `Where("users.age > ?", 25)`：添加了年龄大于 25 的过滤条件。
  + `Order("users.name desc")`：按用户姓名降序排列。
  + `Limit(10)`：限制结果集为 10 条记录。

* **关联部分**：
  + `Joins("Company")` 和 `Joins("Manager")`：加载 `Company` 和 `Manager` 的关联数据。
  + `Where("companies.name = ?", "Tech Corp")`：在关联的 `Company` 表上添加过滤条件，筛选公司名称为 "Tech Corp" 的用户。

### 结果：

* 返回的 `users` 列表中，每个 `User` 对象都包含 `Company` 和 `Manager` 的信息。
* 只包括年龄大于 25 且公司名称为 "Tech Corp" 的用户。
* 按姓名降序排列，最多返回 10 个用户。

这种查询通过组合多个条件和关联，灵活地从数据库中获取所需的数据。

## 增加复杂度2

好的，我们可以再增加一些复杂性，比如引入更多的关联和条件。假设我们还想查询用户的 `Account` 信息，并根据账户类型进行过滤，同时添加更多的排序和条件。

### 假设的结构体

```go
type User struct {
    ID      int
    Name    string
    Age     int
    Company Company
    Manager Manager
    Account Account
}

type Company struct {
    ID   int
    Name string
}

type Manager struct {
    ID   int
    Name string
}

type Account struct {
    ID   int
    Type string
    Balance float64
}
```

### 复杂查询示例

```go
var users []User
db.Joins("Company").Joins("Manager").Joins("Account").
    Where("users.age > ?", 25).
    Where("companies.name = ?", "Tech Corp").
    Where("accounts.type = ?", "Premium").
    Where("accounts.balance > ?", 1000).
    Order("users.name desc").
    Order("accounts.balance asc").
    Limit(10).
    Offset(5).
    Find(&users)
```

### 解析

* **主查询**：
  + `Find(&users)`：从 `User` 表中获取记录。
  + `Where("users.age > ?", 25)`：筛选年龄大于 25 的用户。
  + `Order("users.name desc")`：按用户姓名降序排列。
  + `Limit(10)`：限制结果集为 10 条记录。
  + `Offset(5)`：跳过前 5 条记录，用于分页。

* **关联部分**：
  + `Joins("Company")`、`Joins("Manager")`、`Joins("Account")`：加载 `Company`、`Manager` 和 `Account` 的关联数据。
  + `Where("companies.name = ?", "Tech Corp")`：筛选公司名称为 "Tech Corp" 的用户。
  + `Where("accounts.type = ?", "Premium")`：筛选账户类型为 "Premium" 的用户。
  + `Where("accounts.balance > ?", 1000)`：筛选账户余额大于 1000 的用户。
  + `Order("accounts.balance asc")`：按账户余额升序排列。

### 结果

* 返回的 `users` 列表中，每个 `User` 对象都包含 `Company`、`Manager` 和 `Account` 的信息。
* 只包括符合所有条件的用户。
* 结果按姓名降序和账户余额升序排列，支持分页。

通过这种方式，可以灵活地从数据库中获取复杂的关联数据，满足多种业务需求。

## 增加复杂度3

好的，我们可以进一步增加复杂性，比如引入子查询、更多的关联以及动态条件。

### 假设的结构体

```go
type User struct {
    ID      int
    Name    string
    Age     int
    Company Company
    Manager Manager
    Account Account
    Role    Role
}

type Company struct {
    ID   int
    Name string
    Location string
}

type Manager struct {
    ID   int
    Name string
}

type Account struct {
    ID      int
    Type    string
    Balance float64
}

type Role struct {
    ID   int
    Name string
}
```

### 更复杂的查询示例

```go
var users []User
db.Joins("Company").Joins("Manager").Joins("Account").Joins("Role").
    Where("users.age > ?", 25).
    Where("companies.name = ?", "Tech Corp").
    Where("accounts.type = ?", "Premium").
    Where("accounts.balance > ?", 1000).
    Where("roles.name IN (?)", []string{"Admin", "User"}).
    Where("companies.location = ?", "New York").
    Where("users.id IN (?)", 
        db.Table("user_roles").Select("user_id").Where("role_id = ?", 1).
    ).
    Order("users.name desc").
    Order("accounts.balance asc").
    Limit(10).
    Offset(5).
    Find(&users)
```

### 解析

* **主查询**：
  + `Find(&users)`：从 `User` 表中获取记录。
  + `Where("users.age > ?", 25)`：筛选年龄大于 25 的用户。
  + `Order("users.name desc")` 和 `Order("accounts.balance asc")`：按姓名降序和账户余额升序排列。
  + `Limit(10)` 和 `Offset(5)`：分页控制。

* **关联部分**：
  + `Joins("Company")`、`Joins("Manager")`、`Joins("Account")`、`Joins("Role")`：加载 `Company`、`Manager`、`Account` 和 `Role` 的关联数据。
  + `Where("companies.name = ?", "Tech Corp")` 和 `Where("companies.location = ?", "New York")`：筛选特定公司名称和位置的用户。
  + `Where("accounts.type = ?", "Premium")` 和 `Where("accounts.balance > ?", 1000)`：筛选特定账户类型和余额的用户。
  + `Where("roles.name IN (?)", []string{"Admin", "User"})`：筛选角色名称为 "Admin" 或 "User" 的用户。

* **子查询**：
  + `Where("users.id IN (?)", db.Table("user_roles").Select("user_id").Where("role_id = ?", 1))`：使用子查询筛选特定角色 ID 的用户。

### 结果

* 返回的 `users` 列表中，每个 `User` 对象都包含 `Company`、`Manager`、`Account` 和 `Role` 的信息。
* 只包括符合所有条件的用户。
* 结果支持复杂的排序和分页。

通过这种方式，可以构建非常复杂的查询，满足多样化的业务需求。

## 使用 Where 和直接在 Find 或 First 中传递条件的区别

## Find中增加复杂度

在 `Find` 中增加条件可以通过使用 `Scopes` 来实现动态查询。下面是一个更复杂的示例，展示如何在 `Find` 中添加条件：

### 假设的结构体

```go
type User struct {
    ID      int
    Name    string
    Age     int
    Company Company
    Manager Manager
    Account Account
    Role    Role
}

type Company struct {
    ID       int
    Name     string
    Location string
}

type Manager struct {
    ID   int
    Name string
}

type Account struct {
    ID      int
    Type    string
    Balance float64
}

type Role struct {
    ID   int
    Name string
}
```

### 使用 Scopes 的复杂查询

```go
var users []User

// 定义作用域函数
ageScope := func(db *gorm.DB) *gorm.DB {
    return db.Where("users.age > ?", 25)
}

companyScope := func(db *gorm.DB) *gorm.DB {
    return db.Where("companies.name = ?", "Tech Corp").
              Where("companies.location = ?", "New York")
}

accountScope := func(db *gorm.DB) *gorm.DB {
    return db.Where("accounts.type = ?", "Premium").
              Where("accounts.balance > ?", 1000)
}

roleScope := func(db *gorm.DB) *gorm.DB {
    return db.Where("roles.name IN (?)", []string{"Admin", "User"})
}

userRoleSubquery := db.Table("user_roles").Select("user_id").Where("role_id = ?", 1)

db.Scopes(ageScope, companyScope, accountScope, roleScope).
    Joins("Company").
    Joins("Manager").
    Joins("Account").
    Joins("Role").
    Where("users.id IN (?)", userRoleSubquery).
    Order("users.name desc").
    Order("accounts.balance asc").
    Limit(10).
    Offset(5).
    Find(&users)
```

### 解析

* **Scopes**：
  + `ageScope`：筛选年龄大于 25 的用户。
  + `companyScope`：筛选公司名称为 "Tech Corp" 且位置为 "New York" 的用户。
  + `accountScope`：筛选账户类型为 "Premium" 且余额大于 1000 的用户。
  + `roleScope`：筛选角色名称为 "Admin" 或 "User" 的用户。

* **子查询**：
  + `userRoleSubquery`：用于筛选特定角色 ID 的用户。

* **主查询**：
  + `Joins` 用于加载关联数据。
  + `Where` 与子查询结合用于更复杂的条件。
  + `Order`、`Limit`、`Offset` 用于排序和分页。

通过这种方式，你可以在 `Find` 中灵活地添加条件，利用 `Scopes` 提高代码的可读性和可维护性。
