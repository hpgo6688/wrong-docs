## Association, Joins 和 Preload 都用于处理关联关系

在 GORM 中， `Association` , `Joins` 和 `Preload` 都用于处理关联关系，但它们的用途和工作方式有所不同。

### `Association`

* **用途**：用于直接操作关联关系，比如查找、追加、删除关联数据。
* **工作方式**：不执行 SQL 查询来加载主记录，而是直接操作关联关系。
* **示例**：

  

```go
  db.Model(&user).Association("Languages").Find(&languages)
  ```

  这会查找与 `user` 关联的 `Languages` ，不涉及主记录的其他数据。

### `Joins`

* **用途**：用于在查询中连接多个表，通常用于需要条件过滤的复杂查询。
* **工作方式**：生成带有 `JOIN` 子句的 SQL 查询，将结果合并在一起。
* **示例**：

  

```go
  db.Joins("Languages").Find(&users)
  ```

  这会执行一个 `JOIN` 查询，将 `users` 和 `languages` 表连接在一起。

### `Preload`

* **用途**：用于在查询主记录时预加载关联数据。
* **工作方式**：在查询主记录时，自动执行额外的查询来加载关联数据。
* **示例**：

  

```go
  db.Preload("Languages").Find(&users)
  ```

  这会先查询 `users` ，然后为每个用户执行额外的查询来加载其关联的 `Languages` 。

### 总结

* **`Association`**：用于直接操作关联关系，不涉及主记录的其他数据。
* **`Joins`**：用于复杂的条件查询，通过连接表来获取数据。
* **`Preload`**：用于在查询主记录时自动加载关联数据，适合需要完整对象图的场景。

根据具体需求选择合适的方法来处理关联关系。

## 写一个 Association 例子，及查询的结果

当然，这里有一个使用 `Association` 的例子，以及它的查询结果。

假设我们有以下两个模型： `User` 和 `Language` ，它们之间是多对多的关系。

```go
type User struct {
    ID        uint
    Name      string
    Languages []Language `gorm:"many2many:user_languages;"`
}

type Language struct {
    ID   uint
    Name string
}
```

### 使用 `Association` 查找关联数据

```go
var user User
var languages []Language

// 获取用户并查找其关联的语言
db.First(&user, 1) // 假设我们获取 ID 为 1 的用户
db.Model(&user).Association("Languages").Find(&languages)
```

### 查询结果

假设在数据库中，用户 ID 为 1 的用户会说两种语言： `English` 和 `Spanish` ，那么 `languages` 的结果会是：

```go
[
    {ID: 1, Name: "English"},
    {ID: 2, Name: "Spanish"}
]
```

### 解释

* **`db.First(&user, 1)`**：查找 ID 为 1 的用户。
* **`db.Model(&user).Association("Languages").Find(&languages)`**：查找与该用户关联的所有语言。

这种方式直接操作关联关系，不涉及其他不必要的主记录数据加载。
